# RedmineTimeLogger

Консольное приложение на C# для списания трудозатрат в Redmine: показывает норму
и недостачу часов за месяц, находит задачи в статусах **In-Progress / On review /
On approve**, спрашивает, на какую задачу и сколько часов списать, и создаёт запись
только после подтверждения. Если несписанных рабочих дней больше трёх — спрашивает
про отпуск и пересчитывает норму.

Токен Redmine в коде не хранится — приходит извне (переменная окружения или файл).

## Требования

- .NET SDK 10 (проект на `net10.0`); для запуска готовой сборки — .NET Runtime 10.
- Доступ к Redmine (`https://rm.burworld.ru` по умолчанию).

## Ключ доступа (извне)

| Способ | Как |
|---|---|
| Переменная окружения | `REDMINE_API_KEY=…` (сам ключ) |
| Файл с ключом | `REDMINE_API_KEY_FILE=C:\путь\к\redmine-api-key` |
| Файл по умолчанию | `%USERPROFILE%\.dsh\redmine-api-key`, если существует |

```powershell
$env:REDMINE_API_KEY = "<ключ из Redmine → Моя учётная запись → API access key>"
dotnet run --project .\src\RedmineTimeLogger
```

Ключ в выводе не печатается — только источник, откуда он взят.

## Запуск

```powershell
# интерактивно: отчёт → список задач → выбор → подтверждение
.\run.cmd

# то же из PowerShell (если политика запрещает .ps1:
# powershell -ExecutionPolicy Bypass -File .\run.ps1)
.\run.ps1

# только отчёт по месяцу, без интерактива
.\run.cmd --report

# проверить ключ и связь
.\run.cmd --check

# посмотреть, что будет отправлено, ничего не списывая
.\run.cmd --issue 26422 --hours 8 --date 2026-11-19 --dry-run

# списать без вопросов (осторожно: запись создаётся сразу)
.\run.cmd --issue 26422 --hours 8 --date 2026-11-19 -y --comment "MR !66"
```

`run.cmd` и `run.ps1` — тонкие обёртки над `dotnet run --project src\RedmineTimeLogger`.
Можно запускать и напрямую:

```powershell
dotnet run --project .\src\RedmineTimeLogger -- --report
```

Интерактивный сценарий:

```
Трудозатраты: ноябрь 2026 (по 20.11.2026)
  Будни месяца: 15 дн. × 8 ч = 120 ч
  Праздники в будни: 1 дн. → норма с праздниками 14 дн. × 8 ч = 112 ч
  Списано: 40 ч
  Недостача: 80 ч (к норме «только будни») / 72 ч (с учётом праздников)
  Незаполненные дни (10): 02.11.2026, …, 19.11.2026

Отпуск
  Незаполненных рабочих дней: 10 (80 ч) — больше 3.
Указать отпуск? [д/Н]: н

Задачи в работе (In-Progress / On review / On approve)
  1  #26422  In-Progress  0 ч  20.11.2026  Добавить атрибут tool name …
  …

Выберите задачу: 1–8, или введите номер задачи Redmine (#12345):
Сколько часов списать [8]:
Дата списания (ГГГГ-ММ-ДД или ДД.ММ.ГГГГ) [19.11.2026]:
Вид работ [2]:
Комментарий (Enter — без комментария):

Запись о трудозатратах
  Задача: #26422 [In-Progress] …
  Дата: 19.11.2026 (четверг)
  Часы: 8 ч
  Вид работ: Разработка

Списать время? [д/Н]:
```

Перед подтверждением программа предупреждает, если за выбранный день уже есть
записи и сумма превысит дневную норму (например, 20.11 уже 16 ч — «после записи
будет 24 ч. Это больше дневной нормы»), а также если дата попала на выходной,
праздник или отпуск.

## Отпуск

Отпуск — это дни, которые **не входят в норму рабочего времени**. За них нечего
списывать, поэтому они:

- вычитаются из нормы (`Норма по будням` считается без них);
- не попадают в список «Незаполненные дни»;
- не предлагаются как дата списания по умолчанию;
- помечаются в календаре буквой `о`.

### Программа спрашивает сама

Если в месяце **больше трёх** незаполненных рабочих дней, после отчёта появляется
вопрос:

```
Отпуск
──────
  Незаполненных рабочих дней: 10 (80 ч) — больше 3.
  Если часть этих дней была отпуском, укажите периоды — они выйдут из нормы.
  Например: 02.11.2026..23.11.2026

Указать отпуск? [д/Н]: д
Период отпуска (Enter — закончить): 02.11.2026..06.11.2026
  Учтено: 02.11.2026–06.11.2026 (+5 дн.).
  Норма: 88 ч, списано 40 ч, недостача 48 ч, незаполненных дней 6.

Период отпуска (Enter — закончить):
```

Можно ввести несколько периодов подряд, пустая строка — закончить. Норма и
недостача пересчитываются сразу, периоды сохраняются в файл, поэтому в следующий
раз эти дни уже не считаются рабочими. При отказе (`н`) ничего не меняется.

Спрашивается только в интерактивном режиме и только когда нечего списывать больше
чем за 3 рабочих дня: `--report` и запуск с `--issue` (автоматизация) вопрос не задают.

### Задать отпуск заранее

```powershell
# добавить отпуск (сохраняется между запусками)
.\run.cmd --vacation 02.11.2026..06.11.2026

# несколько периодов сразу
.\run.cmd --vacation 02.11.2026..06.11.2026, 23.11.2026
.\run.cmd --vacation 2026-12-01..2026-12-05 --vacation 2026-12-31

# посмотреть, что сохранено
.\run.cmd --vacations

# очистить
.\run.cmd --vacation-clear
```

Формат периода: `02.11.2026..06.11.2026`, `2026-11-02..2026-11-06` или одна дата
(отпуск в один день); разделитель — `..`, `-`, `–`. Несколько периодов в одном
аргументе — через запятую.

Файл: `%APPDATA%\RedmineTimeLogger\vacations.json`, путь можно переопределить
переменной `REDMINE_VACATIONS_FILE`. Расположение и содержимое:

```json
{ "vacations": [ "2026-11-02..2026-11-06" ] }
```

Разовый отпуск без изменения файла — переменная окружения:

```powershell
$env:REDMINE_VACATIONS = "02.11.2026..06.11.2026"
```

Пересекающиеся и соседние периоды склеиваются автоматически.

Пример отчёта с отпуском:

```
  Будни месяца: 16 дн. × 8 ч = 128 ч
  Отпуск: 6 дн. (02.11–06.11, 23.11) → не учитывается
  Норма по будням: 10 дн. × 8 ч = 80 ч
  Списано: 40 ч
  Недостача: 40 ч (к норме «только будни»)
  Незаполненные дни (5): 09.11.2026, 10.11.2026, 11.11.2026, 12.11.2026, 13.11.2026
```

## Как считаются часы

Логика взята из разбора текущего месяца (ноябрь 2026):

- **Норма** — только будни: количество будних дней с 1-го числа по сегодня × 8 ч,
  за вычетом дней отпуска. За 02.11–20.11.2026 это 15 дней → **120 ч**
  (если отпуска нет).
- **Норма с праздниками** — те же будни минус государственные праздники
  (04.11 — День народного единства) → 14 дней → **112 ч**.
- **Списано** — сумма `time_entries` пользователя за месяц.
- **Недостача** = норма − списано: **80 ч** / **72 ч**.
- **Незаполненные дни** — рабочие дни месяца до сегодняшнего, где нет ни одной
  записи; дни отпуска, праздники и выходные в них не входят.
- Дата по умолчанию для списания — **последний** незаполненный рабочий день.

Праздники: фиксированные даты РФ (1–8 января, 23.02, 08.03, 01.05, 09.05, 12.06, 04.11).
Переносы выходных по постановлениям правительства не учитываются — свои даты можно
передать через `--holidays 2026-12-31,…` или `REDMINE_HOLIDAYS`.

Задачи-кандидаты: открытые задачи, назначенные текущему пользователю, в статусах
`In-Progress` (3), `On review` (15), `On approve` (12) — сначала In-Progress,
затем по дате обновления.

## Параметры

| Параметр | Значение |
|---|---|
| `--issue <N>` | номер задачи; включает неинтерактивный режим |
| `--hours <H>` | часы, например `8` или `4,5` |
| `--date <дата>` | `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ` |
| `--activity <название>` | вид работ, по умолчанию «Разработка» |
| `--comment <текст>` | комментарий к записи |
| `--month <ГГГГ-ММ>` | месяц отчёта (по умолчанию текущий) |
| `--holidays <даты>` | дополнительные нерабочие дни через запятую |
| `--vacation <период>` | добавить отпуск и сохранить (можно повторять) |
| `--vacations` | показать сохранённый отпуск |
| `--vacation-clear` | очистить сохранённый отпуск |
| `--url <адрес>` | адрес Redmine |
| `--report` | только отчёт, без списания |
| `--check` | проверить подключение и ключ |
| `--dry-run` | показать запись, ничего не отправлять |
| `-y`, `--yes` | не спрашивать подтверждение |
| `--insecure` | не проверять TLS-сертификат |
| `-h`, `--help` | справка |

Переменные окружения: `REDMINE_API_KEY`, `REDMINE_API_KEY_FILE`, `REDMINE_URL`,
`REDMINE_HOURS_PER_DAY` (по умолчанию 8), `REDMINE_HOLIDAYS`,
`REDMINE_VACATIONS` (разовый отпуск), `REDMINE_VACATIONS_FILE` (путь к файлу отпусков),
`REDMINE_DEFAULT_ACTIVITY`, `REDMINE_IGNORE_CERT_ERRORS=1`.

## Коды возврата

`0` — успех/отчёт, `1` — отказ от подтверждения, `2` — ошибка аргументов или
конфигурации, `3` — ошибка Redmine API, `4` — сетевая ошибка/TLS.

## Проверка без риска

- `--dry-run` — печатает JSON тела запроса `POST /time_entries.json` и не отправляет его.
- `tools/mock-redmine.mjs` — локальная заглушка Redmine для сквозной проверки:

  ```powershell
  node tools/mock-redmine.mjs 8787
  $env:REDMINE_API_KEY = "0000000000000000000000000000000000000000"
  .\run.ps1 --url http://127.0.0.1:8787 --issue 26422 --hours 8 --date 2026-11-19 -y
  ```

## Проверка

Сборка и запуск проверены в терминале IDE (Passenger): `--check` (реальный Redmine,
пользователь B002441), `--report`, интерактивный сценарий в `--dry-run` и создание
записи против локальной заглушки (`tools/mock-redmine.mjs`) — тело запроса
`{"time_entry":{"issue_id":26422,"spent_on":"2026-11-19","hours":8,"activity_id":7,"comments":"…"}}`
и разбор ответа `201`.

## Замечание про запуск в песочнице агента

Под sandbox'ом DSH Windows-стек TLS (schannel) не получает доступ к хранилищу
учётных данных, и соединение падает с `SEC_E_NO_CREDENTIALS`. Это ограничение среды,
а не приложения: в обычном терминале всё работает. Признак — сообщение
«В пакете безопасности отсутствуют учётные данные».
